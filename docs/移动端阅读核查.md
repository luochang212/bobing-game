# 移动端现场阅读核查

2026-09-12。使用场景：每桌只有一张规则纸，参与者用手机自行阅读、随时查奖。本次只调整网站，不改规则语义、纸质 PDF 或二维码。

## 判断与证据

此前 `f68b702` 版本完成了响应式适配，但没有充分满足“手机快速理解规则”的用途。主要问题是阅读顺序、信息可见性和字号，不需要更换 Astro / Tailwind 架构。

以下为本机 Chrome、390×844 CSS 像素视口的 DOM 实测；纵坐标相对于页面顶部，未模拟弱网。

| 项目 | 调整前 | 调整后 |
| --- | --- | --- |
| 三步玩法起点 | 1128px，首屏之外 | 345px |
| 三步玩法完整读完的位置 | 首屏无法读到 | 688px，完整落在首屏 |
| 无需点击即可阅读的奖级条件 | 1 档，其余藏在标签页中 | 6 档全部展开 |
| 奖级区起点 | 1471px | 876px，另可由目录直达 |
| 状元判定与比较说明字号 | 10px | 16px |
| 导航入口高度 | 约 23px | 50px |
| 阅读中换查章节 | 导航随页面滚走；仅“查奖级、比状元” | 常驻五项目录，含玩法、奖级、状元、结束与异常 |

这些问题会增加查阅动作或阅读难度，判断依据如下：

- 初次扫码时，旧首屏用于口号、主图和打印入口，基本玩法还在下方。已把主图缩为辅助图，首屏直接说明投掷、判奖与领奖。
- 新手往往只知道自己的骰面，不知道奖名。按奖名切换标签页会要求他先完成自己正想查询的判断。现在六档文字条件、示例与份数全部可见。
- 10px 的状元文字属于核心规则，不能当脚注处理。现在手机规则正文以 16px 为主，示例说明最低 14px；用上下排列替代挤在一行的小字。
- “出碗换人”和“碗内无法判读重掷”容易混淆，现直接并列说明。附加问答仍用原生折叠区。
- 将纸面已有的 `2、2、2、2、4、4` 例子展开解释，明确只算四进、四进发完也不改领二举。

参考本机 `genesis-project`，只采用适合短篇规则阅读的部分：

- `skills/frontend-craft/patterns/docs-shell.md`：取自 ccswitch / aihot 的阅读目录思想。本站只需单页常驻目录，不引入三栏布局、搜索框或客户端路由。

## 可重复检查

本轮 Chrome 与 WebKit 两个引擎的七种视口检查均通过，生产构建、原有完整状态机验证及 PDF 单页检查也通过。目录采用即时跳转，不引入滚动动画；“跳到正文”的键盘入口同样预留常驻目录的高度。

回归脚本：[网页阅读验证.py](../verify/网页阅读验证.py)。Playwright 仅为本地验证依赖，不进入网站运行依赖。

先在仓库根目录准备浏览器环境：

```sh
python3 -m venv tmp/reading-check
./tmp/reading-check/bin/pip install playwright
./tmp/reading-check/bin/python -m playwright install chromium webkit
```

构建并启动预览；PDF 的复制步骤与部署工作流一致：

```sh
cd site
npm run build
cp ../output/pdf/博饼规则-A4黑白.pdf dist/rules-paper.pdf
npm run preview -- --host 127.0.0.1 --port 4322
```

再从仓库根目录运行：

```sh
./tmp/reading-check/bin/python verify/网页阅读验证.py
./tmp/reading-check/bin/python verify/网页阅读验证.py --browser webkit
```

使用已安装的 Chrome 可将第一条检查改为 `--channel chrome`。其他预览地址用 `--url` 指定，地址需以 `/` 结尾。

覆盖范围：

- 320、360、390、430、768、1024、1440px 七种宽度，无横向溢出。
- 390×844 下，三步玩法全部落在首屏；状元核心文字不小于 16px。
- 六档条件、六种状元等级与两类异常处理直接可见。
- 13 组显示骰面均能在 LaTeX 的骰面图或文字例句中找到。
- 目录入口至少 44×44px，鼠标 / 触摸跳转后标题不被常驻目录遮挡；章节链接可直接打开。
- 折叠问答、图片与 PDF 可用，无脚本时也能阅读全部规则。

## 理解效果的验证边界

浏览器检查能验证可读尺寸、可达路径与内容是否呈现，**不能证明真实新手已经看懂，也没有测得真人阅读用时**。Chrome / WebKit 的手机视口模拟不等同于真实 iPhone、安卓或微信内置浏览器测试；本轮未验证线上部署、扫码或弱网。

在现场发布前，可请未参与设计、没玩过本场规则的人独立试读，并用下面几道题核对理解：

| 场景题 | 应能独立说出的处理 |
| --- | --- |
| 掷出 222244，该领什么？四进发完呢？ | 只算四进；发完空过，不改领二举 |
| 有一颗出碗，与全部在碗内但叠骰，分别怎么办？ | 出碗本次无效换人；碗内看不清经同桌确认，六颗全重掷 |
| 四红带点总和 12，能赢五红带 1 吗？ | 不能，先比等级，五红更高 |
| 掷到状元时立刻领奖吗？同级同点谁领先？ | 只记名次，最后发奖；先得者保留 |
| 普通奖发完就立刻结束吗？ | 先补完当前一轮，有状元领先者再结束；无人博到则依结束条款继续 |

如果答错，应先观察读者在哪里误读或找不到，再改对应说明；不要用提示后的正确回答代替独立理解。
